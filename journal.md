## 2. Что можно переиспользовать из проекта futures-lab

futures-lab (`/Users/anton/Documents/app/futures-lab`) закрыл этапы 0-4: полный
ML-пайплайн по 4 сериям (CNYRUBF, IMOEXF, SBERF, BR). Журнал — 34 раздела,
сводка в разделе 29, статус в разделе 34.

### Главный результат (проверен на 3 рынках из 4)
- Сигнал живёт в БАЗИСЕ (отклонение фьючерса от справедливой цены), а не в цене:
  AUC 0.70-0.80 с базисом против 0.51-0.54 без него (валюта, индекс, акция).
- Без спота/справедливой цены рынок не исследован: BR — «не проверен», а не «сигнала нет».
- Знаки и веса признаков совпали между рынками: `basis_z` (−), `mom_50_z` (+),
  `vol_ratio` (−). Это довод в пользу единого механизма.

### Что берём как есть
1. Формула базиса (rate parity): `theory = spot × (1 + r_руб × T/365) / (1 + r_CN × T/365)`,
   `basis = (F / scale − theory) / theory` — `processing/features.py:136`.
   Все входные данные у нас уже есть: `spot_currency`, `rates_cbr_fx`, `rates_china`.
2. Стационарные признаки v2 (`add_derived_features`): `basis_z`, `basis_chg_20`,
   `vol_ratio`, `ret_1_z`, `mom_10_z`, `mom_50_z`. Сырые уровни не работают —
   adversarial validation показал различимость train/test с AUC 0.96.
3. Разметка Triple Barrier + веса по uniqueness — `processing/labeling.py`, чистые
   функции, переносится на Polars. Там же зеркальная разметка для шорта (`side=-1`).
4. Дисциплина проверки: purge/embargo, walk-forward внутри train, test открывается один
   раз, издержки по спреду своего контракта — `scripts/walkforward_eval.py`,
   `final_eval.py`, `backtest.py`.
5. Правило ролла: лидер по дневному обороту максимумом (а не парное сравнение) и переход
   только после 2 дней подтверждения — `processing/etf_trick.py:47`. У нас уже похожее
   (среднее за 3 дня), но стоит помнить, почему парное сравнение ломается на разреженной истории.
6. Граница торгового дня — разрыв между свечами > 180 минут, а не расписание сессий
   (расписание FORTS менялось 5 раз) — `db/calendar.py:29`.

### Ловушки (раздел 29.4 журнала futures-lab)
- Наивная склейка контрактов встык рисует «доходность из воздуха» (+64.5% у CNYRUBF).
- Дальние контракты в выборке портят результат (у нас ролл уже по объёму — проверить).
- `fillna(0)` в издержках молча превращает бэктест в бэктест без издержек.
- Carry (календарный спред) похож на базис, но это другой признак (AUC 0.500 против 0.768).
- Raw contract-id нельзя делать признаком: контракт умирает, в проде будет unseen category.
- Масштаб котировки: у MIX/SR цена = базовый актив ×100. Проверить у нас перед расчётом
  базиса по MIX/MXI (`ROOT_TO_PRICE_SCALE` в futures-lab).
- В минутных данных есть свечи выходных (~2.2%) — фильтровать по факту, а не по календарю.
- Ёмкость — главная неизвестная между «числами» и «стратегией»: у CNYRUBF безубыточность
  только от ~2 млрд ₽ (раздел 31).

## 3. Сопоставление со слоем исполнения OsEngine
- В OsEngine оффлайн-склейки рядов (continuous futures) нет. Проблема экспирации 
  решается исключительно на уровне исполнения робота (`BotTabScreener` / `GetFuturesToTrade`):
  робот в рантайме переключает серии по правилу «3–100 дней до экспирации» 
  и принудительно выходит из позиции за 3 дня до даты `Expiration` (в арбитраже — за 7 дней).
- Вывод для NewSt: подход OsEngine подходит для живого трейдинга (live execution), 
  но непригоден для ML-исследований (нет длинного непрерывного ряда для индикаторов). 
  Наш путь (оффлайн-склейка по обороту + ETF Trick NAV для фичей/таргетов) подтвержден 
  как необходимый именно для слоя исследований. 
- Правило выхода за 3–7 дней до экспирации берём на заметку для нашего будущего 
  модуля исполнения (`src/backtest/`).
