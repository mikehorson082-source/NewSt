## Этап 2. Математическое ядро сателлита (2–3 недели)

### Шаг 2.1. Сигнал TSMOM (Time-Series Momentum)

Расчет комбинированного моментума по окнам 1, 3 и 6 месяцев:

$$Signal_t = \text{sign}\left(0.2 \cdot \text{sign}(r_{1m}) + 0.4 \cdot \text{sign}(r_{3m}) + 0.4 \cdot \text{sign}(r_{6m})\right)$$

* Если $Signal_t \ge 0.2 \rightarrow \mathbf{+1}$ (Лонг).
* Если $Signal_t \le -0.2 \rightarrow \mathbf{-1}$ (Шорт).
* При промежуточных значениях $\rightarrow \mathbf{0}$ (Кэш / Вне рынка).

### Шаг 2.2. Модель Log-HAR-J (High-Frequency Realized Volatility + Jumps)

Расчет внутридневных компонент на основе 5-минутных лог-доходностей ($r_{t,i}$):

1. **Реализованная волатильность ($RV_t$):**

$$RV_t = \sum_{i=1}^{M} r_{t,i}^2$$


2. **Бипауэр-вариация ($BPV_t$):**

$$BPV_t = \frac{\pi}{2} \frac{M}{M-1} \sum_{i=1}^{M-1} \vert{}r_{t,i}\vert{} \cdot \vert{}r_{t,i+1}\vert{}$$


3. **Компонент дискретных скачков ($J_t$):**

$$J_t = \max(RV_t - BPV_t, 0)$$


4. **Прогноз волатильности на завтра ($\sigma_{pred}$):**
Оценивается OLS в логарифмах для предотвращения отрицательных значений:

$$\ln(RV_{t+1}) = \beta_0 + \beta_d \ln(RV_t) + \beta_w \ln(\overline{RV}_{5d}) + \beta_m \ln(\overline{RV}_{22d}) + \beta_J \frac{J_t}{RV_t + \epsilon}$$


$$\sigma_{pred} = \sqrt{\exp(\widehat{\ln(RV_{t+1})}) \times 252}$$



### Шаг 2.3. Модуль квантильного сайзинга под депозит 150 000 ₽

Поскольку дробление контрактов на MOEX невозможно, непрерывная формула $w = \sigma_{target} / \sigma_{pred}$ переводится в дискретные правила:

| Инструмент  | Базовый размер | При низкой вол-ти ($\sigma_{pred} < 0.75 \times \text{Med}$) | При высокой вол-ти ($\sigma_{pred} > 1.3 \times \text{Med}$) | Jump-сброс ($J_t / RV_t > 0.30$) |
| ----------- | -------------- | ------------------------------------------------------------ | ------------------------------------------------------------ | -------------------------------- |
| **CNYRUBF** | 4 лота         | 6 лотов                                                      | 2 лота                                                       | 1-2 лота                         |
| **SBERF**   | 2 лота         | 2 лота                                                       | 1 лот                                                        | 1 лот                            |
| **Si**      | 1 лот          | 1 лот                                                        | 0 лотов                                                      | 0 лотов                          |

*Приоритет по ГО:* если модель дает одновременный сигнал на вход по всем трем активам с максимальным сайзом, суммарное требуемое ГО (~35 000 ₽) не превышает установленный лимит в 75 000 ₽.

## Этап 3. Бэктестинг и калибровка издержек (2 недели)

1. **Purged Walk-Forward CV:**
* Окно обучения: 504 торговых дня (2 года).
* Окно тестирования: 63 дня (1 квартал).
* Embargo: 5 дней между обучающей и тестовой выборками.


2. **Тестирование издержек в условиях ручного исполнения:**
* Комиссия: 1.5 ₽ / контракт.
* Проскальзывание: **2 тика** в базовом сценарии (учитывает задержку в 1–2 минуты при выставлении заявки руками в приложении ВТБ).


3. **Метрики валидации:**
* Deflated Sharpe Ratio (DSR) > 0.55.
* Probability of Backtest Overfitting (PBO) < 0.30.
* Максимальная просадка всего портфеля за историю (включая шоки 2022–2024 гг.) $\le 8.5\%$.

### Шаг 4.2. Telegram-бот с интерактивным подтверждением

Скрипт формирует дельту: $\Delta = Target - Current$. Если $\Delta = 0$, в чат отправляется информационное сообщение «Без изменений». Если $\Delta \neq 0$, формируется карточка действия с кнопкой.

```python
# Пример генерации сообщения ботом
text = (
    "🔔 <b>Ребалансировка сателлита | 18:45 МСК</b>\n\n"
    f"📊 <b>Режим:</b> Волатильность {vol_regime}, Jump: {jump_pct:.1f}%\n"
    "🎯 <b>Требуемое действие:</b>\n"
    f"• <b>{action} {abs(delta_lots)} лот(а) {ticker}</b>\n"
    f"• Ориентир цены (Bid/Ask): ~{market_price}\n"
    f"• Целевая позиция станет: {target_lots} лот(ов)\n\n"
    "<i>Откройте «ВТБ Мои Инвестиции» и подтвердите факт исполнения:</i>"
)
# Клавиатура: [ ✅ Исполнено ] [ ❌ Пропустить ]

```

При нажатии «Исполнено» бот обновляет запись в `state.db`, фиксируя актуальное состояние счета.

### Шаг 4.3. Автоматизация на macOS через `launchd`

Для запуска по расписанию в macOS используется системный демон `launchd`. В отличие от стандартного Linux-cron, `launchd` умеет корректно обрабатывать состояния сна ноутбука.

Создается конфигурационный файл `~/Library/LaunchAgents/com.quant.assistant.plist`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>com.quant.assistant</string>
    <key>ProgramArguments</key>
    <array>
        <string>/Users/username/.local/bin/uv</string>
        <string>run</string>
        <string>/Users/username/QuantAssistant/run_daily.py</string>
    </array>
    <key>StartCalendarInterval</key>
    <dict>
        <key>Hour</key>
        <integer>18</integer>
        <key>Minute</key>
        <integer>42</integer>
    </dict>
    <key>StandardOutPath</key>
    <string>/Users/username/QuantAssistant/logs/stdout.log</string>
    <key>StandardErrorPath</key>
    <string>/Users/username/QuantAssistant/logs/stderr.log</string>
</dict>
</plist>

```

Активация агента в системе:

```bash
launchctl load ~/Library/LaunchAgents/com.quant.assistant.plist

```

**Решение проблемы закрытой крышки:** в Telegram-бота закладывается команда `/run`. Если в 18:40 ноутбук был закрыт в рюкзаке, вы можете отправить `/run` со смартфона — при первом же открытии крышки скрипт выполнит дорасчет, либо вы можете запустить его вручную в терминале в одну команду.
