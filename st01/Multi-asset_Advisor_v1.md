# Multi-asset Advisor v1

## 1. Цель

Создать торгового советника для ручного исполнения сделок.

Основная задача советника — несколько раз в день анализировать несколько ликвидных рынков, находить качественные торговые возможности и выдавать **не более одной новой торговой идеи одновременно**.

На первом этапе советник не должен автоматически отправлять заявки брокеру.

Капитал для эксперимента: **до 1 млн руб.**

Главный критерий качества — **экономический результат всего капитала после издержек**, а не accuracy модели сама по себе.

---

## 2. Стартовый набор рынков

На первом этапе:

- IMOEXF или MXI — российский фондовый индекс;
- CNYRUBF — юань/рубль;
- BR — нефть Brent;
- фьючерс на золото.

Набор может быть уточнен после проверки качества исторических данных, ликвидности и удобства ручной торговли.

---

## 3. Общая архитектура

```text
Рыночные данные
      ↓
Расчет признаков
      ↓
Базовые стратегии / правила
      ↓
ML-модель оценки качества сетапа
      ↓
Кандидаты на сделки
      ↓
Jev — decision layer
      ↓
TRADE / SKIP / выбор лучшего рынка и стратегии
      ↓
Понятная рекомендация человеку
      ↓
Ручное исполнение сделки
```

---

## 4. Базовые торговые логики

На первом этапе достаточно 2–3 простых стратегий:

- trend-following;
- breakout;
- mean reversion.

Не нужно сразу строить сложную универсальную модель.

Каждая стратегия сначала должна работать как самостоятельный baseline без Jev.

---

## 5. Роль Jev

Jev не используется как основной прогноз цены.

Основная роль Jev — **decision layer / meta-layer**:

- выбрать наиболее интересный рынок;
- определить режим рынка;
- выбрать подходящую торговую логику;
- разрешить или отклонить конкретный сигнал;
- выдать `TRADE / SKIP`;
- при необходимости выбрать между `TREND / MEAN_REVERSION / BREAKOUT / NO TRADE`.

Предпочтительный сценарий для первой проверки Jev:

```text
Базовая стратегия нашла сигнал
        ↓
CatBoost / числовая модель оценила сетап
        ↓
Jev решает TRADE или SKIP
```

Jev должна доказать свою полезность через улучшение out-of-sample экономического результата.

---

## 6. Формат итоговой рекомендации

Пример:

```text
Инструмент: CNYRUBF
Направление: LONG
Стратегия: Breakout

Entry: 13.42–13.44
Stop: 13.35
Target: 13.58

Risk/Reward: 2.3
Риск на сделку: 0.5% капитала
Размер позиции: N контрактов

Режим рынка: TREND
Волатильность: HIGH / RISING

Решение Jev: TRADE

Условие отмены:
не входить, если цена уйдет выше 13.46 до исполнения.
```

Рекомендация должна быть достаточно простой, чтобы сделку можно было выполнить вручную.

---

## 7. Ограничения v1

На первом этапе:

- только ручное исполнение;
- без скальпинга;
- ориентир — 0–2 сделки в день;
- максимум одна новая позиция одновременно;
- без усреднения убыточной позиции;
- размер позиции определяется риском по стопу, а не доступным ГО;
- ограничивается общее использование ГО;
- значительная часть капитала должна оставаться свободной;
- каждая сделка должна иметь заранее определенные Entry, Stop и логику выхода.

---

# 8. Признаки

## 8.1. Цена и доходности

Для каждого инструмента:

- return 5 min;
- return 15 min;
- return 1 hour;
- return 1 day;
- rolling returns на нескольких горизонтах;
- расстояние от локального high / low;
- gap относительно предыдущего закрытия.

---

## 8.2. Trend

Минимальный набор:

- цена относительно EMA/SMA 20;
- цена относительно EMA/SMA 50;
- цена относительно EMA/SMA 100;
- наклон средних;
- сила и устойчивость тренда.

Не требуется использовать большое количество близких по смыслу технических индикаторов.

---

## 8.3. Momentum

Например:

- momentum на нескольких горизонтах;
- ускорение / ослабление momentum;
- согласованность momentum между таймфреймами.

---

## 8.4. Объем и ликвидность

Считать:

- текущий объем;
- rolling average / median объема;
- отклонение объема от нормы;
- volume percentile;
- при доступности — spread и другие признаки ликвидности.

---

## 8.5. VWAP

Минимально:

- VWAP;
- расстояние цены от VWAP;
- направление движения относительно VWAP.

---

# 9. Волатильность

Волатильность является одним из ключевых блоков состояния рынка.

Минимальный набор:

- ATR;
- ATR%;
- realized volatility;
- realized volatility на нескольких окнах;
- отношение текущей волатильности к исторической норме;
- percentile волатильности;
- изменение волатильности;
- режим волатильности.

Режимы:

```text
LOW
NORMAL
HIGH
EXTREME
```

Важно учитывать не только абсолютный уровень, но и динамику:

```text
volatility_level = HIGH
volatility_trend = RISING
```

Переход от низкой волатильности к быстро растущей может быть отдельным сильным признаком.

---

# 10. HAR / HAR-J

Для прогноза волатильности добавить отдельный блок HAR.

## 10.1. HAR-RV

Базовая модель:

```text
RV_next =
    β0
  + β1 * RV_1d
  + β2 * RV_5d
  + β3 * RV_22d
```

Пример признаков:

- `rv_1d`;
- `rv_5d`;
- `rv_22d`;
- `har_rv_forecast_1d`;
- `forecast_vol / current_vol`.

Обычный HAR используется как baseline.

---

## 10.2. HAR-J

HAR-J дополнительно учитывает jump-компонент.

Базовая идея:

```text
Jump = max(RV - BPV, 0)
```

где BPV — bipower variation.

Признаки:

- `bpv_1d`;
- `jump_var`;
- `jump_share`;
- `har_j_forecast_1d`;
- `har_j_forecast / current_vol`.

HAR-J сравнивается с обычным HAR в walk-forward тесте.

Он остается в системе только если дает улучшение out-of-sample результата.

---

## 10.3. Реализация

Предпочтительный стек для расчета признаков:

**Polars**

Базовый pipeline:

```text
5-min bars
   ↓
intraday log returns
   ↓
daily RV
   ↓
BPV
   ↓
Jump
   ↓
HAR / HAR-J
   ↓
volatility features
```

HAR / HAR-J рассчитываются отдельно по каждому рынку.

---

# 11. Cross-asset признаки

Это один из ключевых элементов Multi-asset Advisor.

Нужно учитывать взаимосвязи между:

- нефтью и российским индексом;
- CNY/RUB и российским индексом;
- золотом и risk regime;
- изменением волатильности на разных рынках.

Примеры:

- return BR / return INDEX;
- return CNYRUBF / return INDEX;
- HAR forecast CNY / HAR forecast INDEX;
- синхронный рост волатильности нескольких рынков;
- divergence между инструментами;
- relative momentum;
- cross-asset confirmation.

Пример компактного состояния:

```text
INDEX trend = DOWN
CNY momentum = UP
OIL = WEAK
GOLD = STRONG
cross_asset_confirmation = YES
```

---

# 12. Признаки, передаваемые моделям

## CatBoost / числовая модель

Получает точные числовые признаки:

- returns;
- ATR;
- RV;
- HAR forecast;
- jump share;
- volume;
- VWAP distance;
- momentum;
- trend features;
- cross-asset features;
- time-of-day;
- другие количественные признаки.

---

## Jev

Получает более компактное описание рыночного состояния, например:

```text
trend = UP
momentum = STRONG
volatility = HIGH
volatility_trend = RISING
ATR_percentile = 85
volume = ABOVE_NORMAL
cross_asset_confirmation = YES
setup = BREAKOUT
```

После этого решает:

```text
TRADE
SKIP
```

или выбирает режим / стратегию.

---

# 13. Риск и размер позиции

Для каждого сигнала обязательно рассчитывать:

- Entry;
- Stop;
- Target;
- Risk/Reward;
- риск в рублях;
- риск в процентах капитала;
- размер позиции;
- используемое ГО;
- долю свободного капитала после входа.

Размер позиции определяется **допустимым убытком по стопу**, а не максимальным количеством контрактов, которое позволяет брокер.

---

# 14. Метрики стратегии

Основные экономические метрики:

- total return;
- CAGR / annualized return;
- Max Drawdown;
- Sharpe;
- Sortino;
- Profit Factor;
- expectancy на сделку;
- средний выигрыш;
- средний убыток;
- win rate;
- количество сделок;
- turnover;
- комиссии;
- проскальзывание;
- стоимость удержания позиции;
- максимальное использование ГО;
- доходность всего капитала.

Win rate является вторичной метрикой.

---

# 15. Проверка полезности Jev

Необходимо сравнить минимум две версии:

## Baseline

```text
Признаки
→ стратегия / модель
→ сделка
```

## Jev

```text
Признаки
→ стратегия / модель
→ кандидат на сделку
→ Jev
→ TRADE / SKIP
```

Дополнительно можно сравнить:

```text
A. Простые правила
B. Правила + CatBoost
C. Правила + Jev
D. CatBoost + Jev
```

Сравнение только на walk-forward / out-of-sample данных.

Главный вопрос:

> Улучшает ли Jev экономический результат после всех издержек или только усложняет систему?

---

# 16. Принцип разработки

Система развивается постепенно.

```text
Этап 1
Данные + единый backtest для всех рынков

Этап 2
2–3 простые стратегии без ML

Этап 3
CatBoost / модель оценки качества сетапов

Этап 4
HAR / HAR-J и более развитая модель волатильности

Этап 5
Jev как фильтр / router

Этап 6
Paper / Advisor mode

Этап 7
Ручная торговля малыми позициями
```

Каждый следующий слой добавляется только после проверки, что он улучшает out-of-sample экономический результат.

---

# 17. Принцип v1

Не пытаться построить идеальную систему заранее.

Первая версия должна быть:

- простой;
- воспроизводимой;
- тестируемой;
- понятной пользователю;
- пригодной для ручного исполнения;
- без лишней автоматизации.

Основная исследовательская гипотеза:

> Multi-asset подход + прогноз режима/волатильности + фильтрация качества сделок позволяют выбирать небольшое число более качественных торговых возможностей, чем торговля одного инструмента по одному универсальному сигналу.
