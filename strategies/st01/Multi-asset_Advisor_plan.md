# Multi-asset Advisor: короткий план разработки

## Принятые правила v1

- Рынки-кандидаты: MIX/MXI, CNY/RUB, Brent и золото.
- Не более одной открытой позиции на весь портфель.
- Сигнал рассчитывается после закрытия свечи, вход выполняется по цене открытия следующей свечи. Задержку пользователя не моделируем.
- Все решения принимаются только по данным, известным к моменту сигнала.
- `data/raw` используется только для чтения и никогда не изменяется.
- Доход от других вложений не учитывается: свободные деньги и деньги под ГО приносят 0%. Фонды денежного рынка, депозит под ключевую ставку и ОФЗ не моделируются и не служат бенчмарком. Результат стратегии — только торговый результат по фьючерсам после издержек. Sharpe и Sortino считаются с безрисковой ставкой 0: ставка уже заложена в цену фьючерса, поэтому его доходность — это уже доходность сверх ставки, и вычитать ключевую ставку второй раз нельзя.

## Последовательность

### 1. Аудит данных

Проверить минутные данные четырех рынков: покрытие по времени, пропуски, дубли, объемы, спецификации контрактов и даты экспираций. По результату выбрать конкретный индексный фьючерс и рынки, пригодные для общего периода тестирования.

### 2. Подготовка исследовательских рядов

Собрать непрерывные ряды контрактов. В первой версии дата ряда — календарная дата MSK, включая выходные без переноса на понедельник. Текущий контракт сравнивается с ближайшим следующим допустимым контрактом по среднему дневному обороту (объем в контрактах × цену, рубли) за последние N завершенных календарных дней с данными (N = 3 по умолчанию); переход выполняется, когда средний оборот следующего стал больше. Оборот, а не число контрактов, потому что при смене размера лота (например, TCSI 10 акций → T 1 акция) контракты несравнимы. Усреднение убирает ложные однодневные пересечения, особенно в коротких сессиях выходного дня. Проверка оборота имеет приоритет. Если сигнал не возник, следующий контракт выбирается с начала последнего дня обращения текущего (`LSTTRADE` из локального справочника). По умолчанию запас до этой даты равен нулю, старый контракт в день экспирации не используется. Более ранний календарный переход возможен только при явном задании запаса. Причина перехода, окно усреднения и достижение дедлайна сохраняются отдельно. Возврат к более ранней экспирации запрещен.

Разницу цен контрактов считать по последней общей минуте завершенного дня решения; время и давность этой пары цен сохранять для проверки качества. Реальные цены хранить отдельно от скорректированных, доходность через смену контракта не рассчитывать. Дополнительно строится NAV по ETF Trick: внутри контракта доходность `close/prev_close`, на первом баре нового контракта `close` к вчерашнему закрытию старого, пересчитанному в цены нового через поправку (базис не попадает, ночное движение рынка — попадает), на переходе вычитается заданная издержка (`--roll-cost-bps`). NAV — честная доходность самофинансируемой позиции и база для признаков и таргетов; реальные цены — только для исполнения. Из минутных данных построить 15-минутные свечи. Производные данные сохранять отдельно от `raw`. Расписание исследовательского ряда не моделирует перенос открытой позиции: цены исполнения, закрытие старой позиции до экспирации и издержки определяются отдельно в бэктесте, а при переносе позиции через переход списывается полспреда старого и нового контракта плюс комиссия.

### 3. Единый портфельный бэктест

До разработки стратегий реализовать один симулятор для всех рынков: вход на следующей свече, стоп, цель, выход по времени, комиссии, проскальзывание, размер контракта, ГО и ограничение одной позиции. Если одновременно появились несколько сигналов, выбирать один по заранее заданному правилу.

### 4. Простые стратегии без ML

Начать с двух стратегий: trend/breakout и mean reversion. Для каждой заранее определить сигнал, Entry, Stop, Target и максимальное время удержания. Не подбирать много вариантов индикаторов.

### 5. Честная проверка baseline

Провести walk-forward тест: параметры выбираются только на прошлом, результат измеряется на следующем периоде. Основные показатели: доходность всего капитала после издержек, Max Drawdown, Profit Factor, expectancy и число сделок. Слабые стратегии и рынки исключить.

### 6. Числовая модель

Только для оставшихся сетапов добавить CatBoost. Цель модели — оценивать ожидаемый результат готовой сделки после издержек. Сравнить правила без модели и правила с CatBoost на одинаковых периодах и при одинаковом риске.

### 7. Дополнительные признаки

Последовательно проверить cross-asset признаки, затем прогноз волатильности HAR и HAR-J. Каждый блок добавлять отдельно и оставлять только при устойчивом улучшении out-of-sample результата.

### 8. Jev как последний фильтр

Передавать Jev компактное состояние рынка и уже сформированный кандидат на сделку. Первая задача Jev — только `TRADE` или `SKIP`. Сравнить четыре версии: правила, правила + CatBoost, правила + Jev, CatBoost + Jev. Jev остается в системе только при улучшении результата после издержек на данных, которых она не видела при настройке.

### 9. Paper mode

Несколько недель формировать рекомендации по расписанию без реальных сделок. Проверить стабильность расчета, понятность Entry/Stop/Target и совпадение рекомендаций с логикой бэктеста. После этого переходить к ручной торговле минимальным размером позиции.

## Первый практический результат

Первая законченная версия — не полный советник с Jev, а воспроизводимый отчет по двум простым стратегиям на четырех рынках в едином портфельном бэктесте. Он станет контрольной точкой для оценки всех последующих усложнений.
